# Independent Re-Verification — Vol.1 Ch01–12 PDF-Direct Fix (2026-09-18)

## Methodology

This is a fully independent re-audit, done without reading `scripts/vol1_chapter_extractor_pdf.py`'s
internal logic or trusting `scripts/support_builder_earth_v2.py`'s corrected values at face value.
`data/raw_pdf/CivilDAR_2019_Vol_1.pdf` (904 pages) was extracted fresh with `pdfplumber` in a new
Python script (page text cached to a scratch JSON), independent of any project script. Chapter page
ranges were taken from the 2026-09-17 audit's own confirmed ranges (Ch01 ≈65–85, Ch03 141–150, Ch04
151–186, Ch05 187–278, Ch06 279–320, Ch07 321–364, Ch08 365–424, Ch09 425–672, Ch10 673–718, Ch11
719–810, Ch12 811–901; Ch02 85–139) and cross-checked against printed footers.

Three passes were run:
1. **Targeted re-check** of every item explicitly flagged as broken/missing in the two 2026-09-17
   audit reports — reading the raw PDF text directly and diffing against the current JSON/script.
2. **Broader random sample** — 5–8 stratified item codes per chapter (first, quartiles, last, plus
   random picks) across Ch01, 03–12 (80 items total), each independently located in the PDF and its
   final "Say" value compared to the JSON `say` field.
3. **Independent coverage scan** — a regex item-code detector (looking for `Code Description Unit
   Quantity Rate Amount` header + a terminal "Say" within the same block) run over each chapter's PDF
   text, diffed against the JSON's code set to surface any remaining/new absentee items. Every
   candidate gap surfaced by this scan was manually resolved.

## New finding: Ch02 item 2.10.1.2 is still wrong (different wrong value)

`scripts/support_builder_earth_v2.py` line 419 hardcodes `"dsr_rate":315.05` for `2.10.1.2`. The PDF
(p.94) computes Say **364.20** for this item (110 m pipe run, 84.89 cum × (252.30+219.65) = 40,063.84,
÷110 = 364.22 → Say 364.20), and this exact value is independently corroborated on p.95, where item
2.11 references "`2.10.1.2 Rate as per Item Number 2.10.1.2 of SH:Earth Work ... 364.20`" as a
cross-check. The 2026-09-17 audit found this item wrong at 417.35; the 2026-09-18 fix changed it to
315.05, which is a *different* wrong value, not a correction — sibling items 2.10.1.1 (223.00) and
2.10.1.3 (568.60) in the same family are both correctly fixed, so this looks like an isolated
transcription slip in the fix rather than a systemic recurrence of the original overstatement bug.

## Known, already-accepted exception (not a new issue)

`support_builder_earth_v2.py` contains four `.2` "Hard soil" variant items (e.g. `2.2.2`, and three
siblings) explicitly commented `# UNVERIFIABLE Hard-soil variant ... Kept as-is per user decision`.
Independent search confirms these sub-items genuinely do not exist in the PDF under those codes. This
matches the prior investigation recorded in project memory (`fix_pdf_deletion_gaps_2026-09-18.md`) and
is not a regression — it is a documented, accepted limitation.

## Broader independent sample (80 items, Ch01, 03–12)

Stratified samples (first/quartiles/last/random) were drawn from every chapter's JSON and each was
located in the PDF independently; all 80 `say` values matched exactly. Five apparent mismatches from
an automated regex pass (5.49, 8.32, 10.15.1, 10.25.1, 10.31) were manual-read and confirmed to be
**false negatives of the checking script** (it grabbed an earlier in-body "Say X kg" sub-calculation
line instead of the item's true final Say) — not real data errors. No new discrepancies were found in
this sample.

## Coverage scan for remaining/new gaps

An independent regex-based item-code/table scanner was run per chapter and diffed against the JSON
code sets. It surfaced many candidates, but manual triage confirmed **every single one** was a false
positive of the same two kinds the 2026-09-17 audit had already identified: (a) bare parent group
headings (e.g. `6.1`, `8.14`, `12.42`, `9.106` — verified all have their real sub-items `6.1.1`,
`8.14.1.x`, `12.42.1`–`.6`, `9.106.1`/`.2` etc. present in JSON) and (b) cross-reference lines inside
other items' resource tables (e.g. "`3.8 Rate as per Item Number 3.8 of SH: Mortars`" inside a Ch08/11
item). No genuine new coverage gap was found in Ch01, 03–12. Ch01's carriage rate-matrix rows
(1.1.1–1.1.17, 1.2.1–1.2.17) remain intentionally excluded from `ch01_items.json` — they are large
multi-column freight-rate lookup tables, not discretely priced items with a "Say" line, and this
scoping predates and is unrelated to the 2026-09-18 fix.

## Verdict

**Yes, with one caveat.** Every item explicitly flagged as broken or missing by the 2026-09-17 audits
is now confirmed correct by independent PDF re-extraction — the mortar 3.18/3.19 merge, the Ch05
above-plinth rebar family, the Ch05 5.4/5.7/5.12–5.17/5.48 items, the entire Ch09 uPVC window/door
family (20 items), Ch06 6.5, Ch07 7.19, Ch11 11.37A/11.46A, Ch12 12.52.1, and 10 of the 11 Ch02
`dsr_rate` items, plus the Ch02 2.16.1–2.16.3 resource-row corruption. The broader 80-item random
sample across all 11 chapters and an independent coverage scan turned up no new regressions or gaps.

The one exception is **Ch02 item `2.10.1.2`**, whose `dsr_rate` is still wrong (315.05 instead of the
PDF-confirmed 364.20) — a leftover/newly-introduced single-item error, not a systemic recurrence. This
should be corrected before Ch02 is considered fully reconciled; everything else re-verified in this
pass holds up.
