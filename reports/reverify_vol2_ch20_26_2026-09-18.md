# Re-Verification Audit — Vol.2 Ch.20–26 vs Raw PDF (post-fix)

Date: 2026-09-18
Scope: `data/raw_pdf/CivilDAR_2019_Vol_2.pdf` pages 855–1110 (0-indexed) vs current `data/reference_json/ch{20..26}_items.json`, after the 2026-09-18 fix to `scripts/vol2_chapter_extractor.py`.
Question: does the fix actually hold up under independent re-verification?

## Methodology

Independent Python/pdfplumber extraction, run fresh against the raw PDF (the extractor's source code was **not** read or trusted). Steps:
1. Re-dumped each chapter's page range to plain text via pdfplumber directly.
2. Re-confirmed PDF length (1110 pages) and that page index 1109 is blank with real content ending at 1108 — matching the prior audit.
3. Re-checked the four specific previously-broken items by name (20.1.1, 21.1.1.1/21.1.1.2, 21.4.1 duplicate).
4. Wrote an independent broad regex to enumerate every 4-digit resource code appearing at the start of a text line per chapter, and diffed distinct codes against the codes actually captured in each chapter's JSON resources, to catch coverage regressions (not relying on the extractor's own code-range logic).
5. Checked for duplicate item codes in all 7 JSON files.
6. Wrote an independent item-header regex (`NN.d(.d){0,3}` at line start followed by a capital letter) to enumerate candidate item/section codes per chapter, then diffed against JSON item codes — manually inspecting each "missing" candidate to determine whether it's a real leaf item (should be priced/JSON-present) or just a non-priced parent/section heading (expected absent).
7. Spot-checked 9 items spread evenly across Ch20–23 and Ch26 (first, ~1/8 intervals, last), and exhaustively checked Ch24 (8 items) and Ch25 (7 items), comparing PDF "Details/Detail of cost for..." phrase and "Say" rate against JSON unit/basis/say.

One non-issue ruled out: `ch25_items.json` has 7 items numbered 25.1–25.6 and 25.8 (no 25.7) — verified against the PDF that item number 25.7 genuinely does not exist in the source document; this is not a gap.

## Final verdict

**Does the 2026-09-18 fix hold up under independent re-verification for Vol2 Ch20–26? Mostly, but not completely.**

All four specifically-cited prior defects (20.1.1's unit/basis and missing resources 0024/5.33.1; 21.1.1.1/21.1.1.2 merge; 21.4.1 duplicate) are genuinely fixed, and the systemic problems from the original audit — plural "Details of cost for" phrasing, resource codes outside 0/8/9, multi-line resource descriptions, lowercase cross-reference wording — are now handled in the large majority of cases (resource-code coverage improved from 23–85% loss to single digits/low percentage loss per chapter for Ch20–25, and item-level merge/duplicate bugs are gone chapter-wide).

However, this re-verification surfaced **new, real residual defects**, concentrated in Ch26 (the largest chapter):
1. A block of **14 entire items (26.18.2–26.18.15)** is completely missing from `ch26_items.json`, apparently due to a mid-chapter running page header being misread as a chapter boundary.
2. At least **5 items** (22.14.1, 26.1, 26.49.4, 26.73.1.8, 26.73.3.8) still get the wrong unit/basis because their "Details/Detail of cost for..." phrasing uses variants the current regex doesn't yet cover (spelled-out numbers, multiplication expressions, missing "for", or the alternate "Detail cost of..." wording).
3. Ch26 still has roughly 30 individual resource-row omissions among ~250 distinct codes, and Ch24 still misses one real resource line (code 1034) on item 24.2.

**Recommendation:** the fix is a large, verifiable improvement and safe to keep, but Ch26 in particular should not yet be treated as a fully-accurate substitute for the raw PDF — the missing 26.18.2–26.18.15 items are a material coverage gap, not a rounding error. The raw PDF should be retained until these residual issues (page-header-triggered item loss, additional basis-phrase variants, remaining resource-row gaps) are fixed and Ch26 is re-verified.
