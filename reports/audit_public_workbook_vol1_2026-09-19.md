# Audit: CPWD_DAR_2019_Vol1_PDF_Conversion.xlsx (public-distribution workbook)

Date: 2026-09-19
Scope: `CPWD_DAR_2019_Vol1_PDF_Conversion.xlsx` (Ch01–12, one sheet per sub-head + Cover & Index),
generated by `scripts/generate_public_conversion_workbook.py`.
Audited purely against this repo's own already-verified source data
(`data/reference_json/ch0N_items.json` for ch01, ch03–12; `scripts/support_builder_earth_v2.py`
`ITEMS` for ch02) — no PDFs were opened for this audit.

## Methodology

Wrote three standalone Python/openpyxl scripts (not spot-checks):

1. **Structural parser** — walked all 12 sheets row-by-row, reconstructing each item block
   (header, "Rate basis:" note, either the percentage-note+value or the resource table +
   "Resource Total" + "SAY" rows) purely from cell contents/position, independent of the
   generator's own code, to catch any layout drift the generator itself might not "know" about.
2. **Completeness/value/formula cross-check** — for every one of the 1,083 items across all 12
   sheets, compared the parsed workbook block against the corresponding source record
   (code, description, basis, resources list item-for-item, SAY value or pct value), and verified
   every resource row's Amount formula (`=D{row}*E{row}`) and every item's Resource Total SUM
   range (`=SUM(F{res_start}:F{res_end})`) exactly, for **every item, not a sample** (this exceeds
   the requested ≥100-item formula sample — full population was checked because the automated
   parse made it no more expensive than sampling).
3. **Cover/Index, formatting, and error-value sweep** — cross-checked the Cover & Index sheet's
   per-chapter item counts and internal hyperlinks against actual sheet contents/names; scanned
   every cell in all 12 sheets for Excel error values, stray Python-repr text (`None`, raw
   dict/tuple/list strings), merged-cell ranges with an empty anchor cell (label-loss risk), and
   `Quantity`/`Rate`/`Amount`/`SAY` cells left in `General` number format; verified all Ch02
   percentage-item (`pct_item=True`) entries render with the expected note and `dsr_rate/100`
   percentage value.

## Discrepancies found

**None.** Across all four automated checks (completeness, formula integrity, structural/label
soundness, formatting/error-value sweep), zero discrepancies were found in:

- Item presence/duplication (0 missing, 0 extra, 0 duplicate codes, in either source or workbook)
- SAY values (all 1,077 non-percentage items) and percentage values (all 6 pct items) — exact match
- Every resource row's code/description/unit/quantity/rate (all resource rows, all 12 sheets)
- Every Amount formula (`=D{row}*E{row}`) — correct, own-row reference, no off-by-one, in every
  resource row across all 1,083 items
- Every Resource Total SUM formula range — exactly spans that item's own resource rows, no overlap
  into neighboring items, across every item with resources
- Header code/description text, "Rate basis:" note text, "Resource Total" label, "SAY" label — all
  present and correctly worded, no orphaned/blank labels from merge bugs, across every item
- Cover & Index: all 12 per-chapter item counts match actual sheet contents; all 12 hyperlinks
  target `#'<sheet_name>'!A1` with the sheet existing under that exact name
- No merged range with an empty anchor cell anywhere in the 12 sheets; row heights and column
  widths all within sane bounds
- No Excel error values (`#REF!`, `#VALUE!`, etc.) and no stray Python-repr text anywhere in any
  of the 12 sheets
- No `Quantity`/`Rate`/`Amount`/`SAY` cell left in `General` number format — all use the intended
  `₹ #,##0.00` (currency) or `#,##0.000` (quantity) / `0.00%` (percentage) formats
- Workbook `calcProperties.fullCalcOnLoad = True`, so Excel recalculates all formulas on open
  (cells show blank under `data_only` read only because the file has never been opened/saved by
  Excel itself — this is normal for an openpyxl-generated file, not a defect)

## Observations (not defects, noted for completeness)

- Two Ch02 percentage items, **2.24.1** and **2.24.2** ("Extra rates for quantities of works
  executed: In or under water / In foul positions"), have `dsr_rate = None` in the source
  (`support_builder_earth_v2.py`). The generator's `(pct_value or 0) / 100.0` turns this into a
  displayed **0.00%**, which the workbook faithfully reproduces (matches source exactly, so not a
  cross-check discrepancy) — but a reader could misread "0.00%" as an authoritative zero rather
  than "rate not captured in source data." This is a pre-existing source-data gap, not a generator
  bug, and outside this audit's flagging criteria since it causes no formula/structural failure —
  mentioning only as a possible future polish item (e.g., leaving the cell blank instead of 0.00%
  when `dsr_rate is None`).
- The two intentionally-empty material codes (Blasting powder, Fuse in Ch02) and Kerosene oil in
  2.35.5 render as empty-string code cells as expected, with no downstream formula impact — Amount
  formulas for those rows are correct `=D{row}*E{row}` and Resource Total ranges include them
  correctly.

## Verdict

**Reliable, error-free.** All 1,083 items across all 12 sub-head sheets are complete (no drops,
no duplicates), every SAY/percentage value exactly matches this repo's verified source data, every
resource row and Amount/Resource-Total formula is structurally correct with no off-by-one or
range errors, all labels and Cover & Index cross-references are intact, and no error values,
formatting gaps, or repr artifacts exist anywhere in the file. This workbook is fit to ship as a
public deliverable in its current form. The only note is a cosmetic one (2.24.1/2.24.2 percentage
cells showing 0.00% for source `None` values) that is a pre-existing source-data characteristic,
not a defect introduced by this workbook's generation.
